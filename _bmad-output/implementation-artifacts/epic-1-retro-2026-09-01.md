## 2. Team Discussion

**Amelia (Developer):** "This was the concrete-pour epic. Nothing sexy, but every later epic dies without it. Let's look at what actually shaped the outcome."

**Alice (Product Owner):** "Four stories, one epic, no scope creep. That's rare. What actually went well?"

### 2.1 What Went Well

- **Contract-first stories.** Every story spec named the ACs, the exact DDL, the Pydantic model shape, and the mock pattern. Stories 1.2 and 1.3 read like implementation checklists — the dev agent had almost no room to invent.
- **Learnings propagated forward.** Story 1.2's `database.get_pool()` module-reference-vs-imported-name mock lesson was explicitly carried into Story 1.3's "Previous Story Learnings Applied" table. That table survived into 1.3 and is the single best pattern to keep.
- **Fail-fast on config from day one.** `DATABASE_URL` missing → `sys.exit(1)` at import time. This will save hours of "why is my connection None" debugging across Epics 2–6.
- **Test infrastructure landed early.** `TestClient` + `scope="module"` fixture with pool patching became the reusable template for all downstream test files.
- **Modern FastAPI lifecycle.** Dev agent proactively used `lifespan` instead of the spec's `@app.on_event`. Good judgment call, documented in the Debug Log.

**Charlie (Senior Dev):** "The mock-at-definition-site lesson is the kind of thing that would have wasted a whole afternoon if we hadn't caught it in 1.2 and hardcoded it into 1.3's spec."

### 2.2 What Struggled

- **Story 1.1 has unchecked tasks that were actually done.** Tasks 5 (`health.py` file creation) and 6 (`.env.example`) show `[ ]` in [1-1-scaffold-fastapi-backend-with-postgresql.md](_bmad-output/implementation-artifacts/1-1-scaffold-fastapi-backend-with-postgresql.md) but the File List and Completion Notes confirm they shipped. Task checkbox hygiene drifted from reality.
- **No epic reached `done`.** All Epic 1 (and 2–6) stories sit at `review`. Retrospective was blocked-then-overridden. The `review → done` transition is not owned by anyone in practice.
- **Review Findings ledger is thin.** Only 1.1 has a "Review Findings" section. Stories 1.2–1.4 have `Dev Agent Record` but no explicit review pass captured in the file. Either reviews happened elsewhere and weren't backlinked, or they didn't happen at all.
- **Deferred work has one entry for the whole epic.** [deferred-work.md](_bmad-output/implementation-artifacts/deferred-work.md) captures only the `requirements.txt` versioning-policy defer from 1.1. Either Epic 1 genuinely accrued almost no debt (plausible for a scaffold) or debt wasn't logged (also plausible).
- **`@app.on_event` still shown as reference pattern** in 1.1's Dev Notes even though the dev correctly used `lifespan`. Spec text and implementation drifted.
- **SSE endpoint tested with mocks only.** Story 1.4 confirmed tests pass but there's no evidence of an end-to-end SSE roundtrip against a real client. Epic 2 (frontend) is going to be the first real test of the contract.

**Dana (QA Engineer):** "Unit tests are green but I don't see any integration test that boots the app against a real Postgres. Everything is mocked at the pool level. That's fine for a scaffold epic, but we're accumulating a blind spot."

### 2.3 What Was Learned

1. **Mock at the definition site, not the import site.** `patch("backend.store.database.get_pool")` works; `patch("backend.store.project_store.get_pool")` doesn't, because `project_store` accesses via `database.get_pool()`. This is now the enforced pattern across the codebase — keep it that way.
2. **Pydantic v2 doesn't reject empty strings by default.** `@field_validator(mode="before")` with an explicit `.strip()` check is the pattern. Anywhere else that accepts free-text names must follow it.
3. **asyncpg `Record` is dict-like but not `dict`.** Always convert with `dict(record)` before returning from a store function. JSONB fields decode to native `dict`/`list` — no `json.loads` needed.
4. **`load_dotenv()` in tests must be neutered for fail-fast tests.** Patching `dotenv.load_dotenv` was required in 1.1 to actually test the missing-`DATABASE_URL` exit path. Future fail-fast tests need the same treatment.
5. **UUID path params get free 422 validation from FastAPI.** Don't reinvent — declare `project_id: uuid.UUID`.
6. **SSE messages must terminate with `\n\n`.** Non-obvious, easy to lose in refactors. Bake it into an emitter helper (Story 1.4 did) rather than string-formatting inline elsewhere.

### 5.2 Preparation Tasks Before Epic 2

- **CORS middleware.** Nothing in Epic 1 configured `CORSMiddleware`. Next.js dev on `localhost:3000` calling FastAPI on `localhost:8000` will fail preflight. Add this either as pre-Epic-2 prep or as the first task in Story 2.1.
- **Publish an OpenAPI schema snapshot.** Story 2.1 says "typed REST client." Freeze the current `/openapi.json` so the frontend types generate deterministically.
- **Run action item A4 (real SSE smoke test) before Story 2.3 starts.** Story 2.3 will discover any protocol drift the hard way otherwise.
- **Confirm `publish_event` is importable from the paths Epic 5's execution engine will use.** SSEManager is currently only wired to the `/stream/*` route; Epic 5 will call `publish_event` from the SupervisorAgent. Story 1.4 accepted this but didn't verify the import path is stable.

### 5.3 Risks Flagged for Epic 2

- **SSE + Next.js App Router quirks.** Next.js edge/serverless routing has known SSE friction. The frontend team should confirm they're using the pages/app router pattern that supports long-lived server-sent responses.
- **Project isolation at API boundary is enforced; at UI level it's not yet a thing.** Watch for any Epic 2 story that starts caching project state client-side without a project-id-scoped key.
