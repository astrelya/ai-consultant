Technique 01

Reverse Brainstorming

Start by designing the worst possible AI dev tool imaginable. Each failure mode, when flipped, reveals a concrete design requirement.

▼ Failure Mode user
Design Requirement ▲
Failure

Implement all tickets in parallel → merge conflict hell the user can't resolve because they didn't write the code.

Requirement

Sequential execution — one ticket at a time, with deterministic ordering.

→ sequential execution

Failure

Complete black box — no visibility into agent activity. 3 minutes of silence, then just "success".

Requirement

Live thought log — the user sees exactly what the agent is doing, at every step.

→ live thought log

Failure

Sub-agents have no cross-ticket context — each confidently solves its task in isolation, producing locally correct but globally broken code.

Requirement

Persistent cross-ticket memory — agents share a growing understanding of the codebase across the entire sprint.

→ persistent cross-ticket memory

Failure

Interface overload — too much information surfaced at once. Not user-friendly.

Requirement

Progressive disclosure UI — surface only what the user needs at each stage of the workflow.

→ progressive disclosure UI

Failure

Agent asks for the repo name repeatedly for the same ticket batch — no session memory for basic config.

Requirement

One-time project config — enter project name, repo, and preferences once. The app remembers.

→ one-time project config

Failure

Tester agent reports success but did nothing — ghost validation with no actual test execution.

Requirement

Mandatory test artifacts — every ticket must produce verifiable test output before it's marked done.

→ mandatory test artifacts

💡
Insight

6 core design requirements extracted from the failure map:

  • Sequential Execution
  • Live Thought Log
  • Persistent Cross-Ticket Memory
  • Progressive Disclosure UI
  • One-Time Project Config
  • Mandatory Test Artifacts
Technique 02

Provocation Technique

State something deliberately absurd. Sit with it. Mine the principle hiding underneath the impossibility.

💣
Provocation Statement

"Generated code is always perfect — zero flaws, always using the latest frameworks and libraries."

user
⇒
Principle Mined

Active dependency grounding via Context7. Since generated code can't be perfect, the system must actively verify that every library reference is real, current, and compatible — before it ever writes a line.

🤑
Provocation Statement

"Zero human interaction anywhere — give it a spec, get a finished app, make millions."

user
⇒
Principle Mined

Exception-driven autonomy with confidence thresholds. Full automation is the aspiration, not the default. The agent works autonomously at high confidence — and surfaces to the PM only when it genuinely doesn't know. Human input is reserved, not squandered.

🧠
Provocation Statement

"The app has no memory — every session starts completely fresh, no project history, no previous tickets, no codebase knowledge."

coach
⇒
Principle Mined

Living project memory store that grows across sessions. The value of the system compounds over time. Every ticket completed, every decision made, every edge case encountered becomes part of a persistent project brain — a context layer that makes each session smarter than the last.

Technique 04

Scenario Cross

Map the tool strategy across four uncertain futures. What holds regardless of how the world turns?

AI Capability
↑ Team       User Adoption       Solo ↓
Team + Low AI
The Reliable Junior

Handles simple, well-scoped Jira tickets within an existing team. Jira integration makes it slot in as a new team member — without needing high AI sophistication.

Team + High AI
The Autonomous Team Member

A fully capable agent that handles complex cross-cutting tickets, integrates into standups via Jira, and requires minimal human handholding. The app's ceiling.

Solo + Low AI
The Automation Assistant

Helps a solo dev generate boilerplate, scaffold features, and manage tickets — even at lower AI quality. Interface clarity matters most here.

Solo + High AI
Dev Team in a Box

The primary target: a solo developer with a spec, no team, and an AI agent squad that handles implementation end-to-end. The user is the only human in the loop.

Low AI Capability → High
The AI-Proof Constant

The design bet that survives all four futures: interface quality.
Easy access for every type of user is the most important thing — regardless of AI capability.
