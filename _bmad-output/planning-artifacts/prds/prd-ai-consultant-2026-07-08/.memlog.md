- (decision) Product is open source, not commercial — no monetization, no market personas, no revenue sections
- (decision) Core pain: fuzzy evolving ideas cause context loss across AI sessions; AI destroys existing work when started fresh without knowing what already exists
- (decision) Product name: ai-consultant. Core value is project continuity — persistent, project-scoped memory so agents always know what was built, decided, and why — not raw speed
- (decision) Primary user: solo developer / small team member with ideas to execute. Success metric: app works and produces good usable projects from a user idea — no vanity metrics
- (decision) Three project entry paths: (1) brainstorm path — user describes idea, app runs BMad brainstorm pipeline and produces spec; (2) spec review path — user provides spec, app guides through BMad validation/refinement; (3) direct path — user has ready spec, goes straight to implementation
- (decision) Jira integration is optional — implementation can proceed with spec documents only, no tickets required. Ticket creation is an optional step the user chooses to take or skip.
- (decision) Multiple projects can run simultaneously; user selects active project from a project list on app open. Spec stored in two places: in the app (for agent memory/history) and in the project repo (for the user).
- (decision) Agent pause flow: agent posts clearly-worded stop message in chat stating why; offers three actions: continue (if confident enough), request user clarification, or abandon ticket; after user responds — if agent understands, auto-resumes; if still uncertain, re-prompts for clarification. All in chat, no separate UI panel.
- (decision) Error escalation model: (1) if logs are insufficient, agent adds logging instrumentation first to gain full visibility; (2) if still unresolvable, agent produces a full error report with complete logs, pushes branch with explicit commit message flagging the error; (3) all generated projects must have a logger configured from the start so users can trace errors during testing.
- (decision) Approval gate: only required when Jira is used (user reviews/edits tickets before execution). No-Jira path has no approval gate — brainstorm completion = implicit approval; direct spec request = immediate execution. Chat view streams logs + per-ticket elapsed time + current status indicators during execution.
- (decision) UI is hybrid chat + structured components (not pure text). Ticket review: structured card view in chat, inline editable fields; two controls: Accept button (calls Jira API directly, no LLM) + text field (calls LLM for revision). Implementation selection: same card view with checkboxes per ticket; backend resolves dependency order (blocking/blocked-by) before execution begins. Minimize LLM calls — UI actions that don't require reasoning go direct to API.
- (decision) Deployment: git clone + uv/pip, plus Docker. No hosted option. Token consumption and estimated cost displayed per session and project. API keys via .env file — no change required for v1.
- (event) PRD draft complete — prd.md written with 26 FRs across 6 feature groups; 4 open questions; 6 assumptions
- (decision) OQ1 resolved: confidence threshold removed — concept does not exist in codebase. Agent pauses when genuinely uncertain (no numeric threshold). OQ2 resolved: Docker image includes DB; uv/pip users supply their own DB. OQ3 resolved: UI provides explicit mode buttons (Brainstorm / Review Spec / Implement) + LLM can suggest mode switch from context; BMad already in project, invoked as subprocess. OQ4 resolved: one active agent execution at a time across all projects; multiple projects exist but queue sequentially.
