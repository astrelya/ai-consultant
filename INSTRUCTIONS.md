# AI Assistance Instructions (Project-Specific Rules)

This file serves as a strict directive for any an AI agent, tool, or assistant operating on this repository. When you start working on this project, adhere rigorously to the following constraints:

## 1. LLM Model Versions & Best Practices
- **DEPRECATED**: Do NOT use any `gemini-1.0` or `gemini-1.5` series models (e.g., `gemini-1.5-pro`, `gemini-1.5-flash`). These are permanently deprecated in this repository.
- **APPROVED**: Default to modern Gemini models. Use `gemini-3.1-pro` or the generic `gemini-pro`.
- **Frameworks**: When instantiating the LLM, strictly use `langchain-google-genai` and `ChatGoogleGenerativeAI`.

## 2. Architecture Constraints
- **Agent Workflow**: The project mandates a strict hierarchical structure. Do not bypass the `SupervisorAgent`. All task delegation and orchestration MUST flow through `agents/main_agent.py`.
- **Tool Invocations**: Do not build direct HTTP/REST API wrapper classes for external environments (like GitHub). The project integrates **Model Context Protocol (MCP)** via LangChain's `langchain-mcp-adapters` and requires external systems to be exposed as standard MCP tools.
- **Environment Management**: Development must only take place inside isolated folders generated by the `EnvironmentAgent` representing cloned repositories (`./workspaces`). Do not write artifacts directly into the root folder unless modifying the core system architecture.
- **Asynchronous Processing**: Ensure any new agents or workflows leverage standard `asyncio` logic, as the underlying `mcp` SDK demands asynchronous execution loops mapping natively to LangGraph primitives.

## 3. Libraries & Dependencies
- Strictly restrict system-level changes from overriding the pinned libraries in `requirements.txt`.
- Do not utilize raw `mcp` SDK to manually map definitions unless absolutely necessary. Rely on the `langchain-mcp-adapters` context manager wrapper to ingest tools.
