- (decision) AD-1 Paradigm: Layered + Supervisor-Worker Agent. Four layers: Frontend (Next.js), Backend API (FastAPI), Agent Orchestration (LangGraph Supervisor→Workers), Persistence. Prevents: mixed concerns, cross-layer shortcuts, agent-to-agent direct calls.
- (decision) AD-2 Strict agent hierarchy: SupervisorAgent → (EnvironmentAgent, LocalDeveloperAgent | RemoteDeveloperAgent, TesterAgent). Sub-agents never call each other. [ADOPTED] — already in project-context.md.
- (decision) AD-3 MCPManager singleton — all MCP connections through MCPManager.get_instance(). [ADOPTED] — already enforced in project-context.md.
- (decision) AD-4 Global sequential execution lock — one active ticket across all projects at a time, enforced at SupervisorAgent. Prevents concurrent agent processes. Rule: SupervisorAgent checks lock before starting any ticket; lock released only on full ticket close (test artifact written, status updated).
- (decision) AD-5 Project isolation — each project has a fully isolated store (own agent memory, spec, ticket history, cost ledger); no shared mutable state between projects. Prevents cross-project context leakage.
- (decision) AD-6 Test artifact gate — TesterAgent writes a test artifact reference to the project store before any ticket status transitions to Done. Prevents ghost validation. Rule: missing artifact reference is a system error, not a silent pass.
- (decision) AD-7 Streaming over polling — agent log output and status updates delivered to frontend via SSE. Prevents batched output, UX gaps. Rule: backend emits log lines as they are produced; frontend subscribes to SSE endpoint per active execution.
- (decision) AD-8 Context7 grounding mandatory — a Context7 query must precede every code generation step in DeveloperAgent. Result incorporated into generation prompt. Prevents hallucinated or stale API usage (FR-14, CAP-8).
- (decision) AD-9 Async throughout agent layer — all agent invoke calls use ainvoke; no synchronous LLM or agent executor calls. [ADOPTED] — enforced in project-context.md.
- (decision) AD-10 Frontend-backend boundary: REST + SSE — frontend communicates via REST for actions, SSE for streaming; never accesses project store or agent layer directly. Prevents tight coupling, direct DB calls from browser.
- (decision) AD-11 BMad pipelines invoked as subprocesses — brainstorm and spec validation pipelines called via Python subprocess from backend; output piped back to SupervisorAgent for streaming. [ASSUMPTION] wiring detail (subprocess stdout → SSE) is an architecture spike item.
